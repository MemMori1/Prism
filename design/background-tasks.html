后台任务坞 & 终端侧栏

一次会话里往往不止一件事在跑：构建、测试、脚本、另一个 Agent。现在它们只能挤在对话流里，或者去系统终端里另开一个窗口。 这份设计把「正在后台跑的东西」收进输入框正上方的一条 35px 的坞：折叠时只是状态条，展开才让出视线； 切换会话一律自动折叠，任务不中断。文件侧栏补一个「终端」页，作为这些进程的深水区——新建、看全量输出、继续输入命令。

设计说明

为什么是这个位置、这套折叠规则、以及落地要动哪些文件
01 / 位置

贴着输入框，而不是顶栏或独立面板

后台任务是「我这一轮在做的事」的延长线，视线本来就落在输入区。放到顶栏会把任务和会话割开，放到右侧又会和文件、工坊抢宽度； 贴在输入框上方时，35px 折叠条 + 一行计数就够表达「还有东西在跑」，展开面板向上浮起、遮住时间线而不是把输入框往下推， 输入区位置始终不动。

面板宽度和输入框对齐（同样是 max-width 1000px），视觉上就是输入框长出来的一层，不是另开一个浮层体系。 和权限卡叠放时顺序是：坞在上面，权限卡仍紧贴输入框——越急的东西离手越近。

02 / 折叠规则

只在「该看」的时候打开

切换会话立即折叠 任务继续跑，不打断
点 ✕ / Esc折叠 不结束任务
新建任务自动展开 新行高亮 3s
等待审批折叠条转琥珀 计数 + 脉冲点
任务失败只把计数标红 不抢折叠条的颜色
全部结束保留 10s 再淡出，只留最近一条
03 / 信息层级

条 → 行 → 输出，三层渐进

条回答「有没有事、几件事」：状态点 + 三个计数 + 最前任务的命令与用时。
行回答「哪件事、在哪跑、多久」：等宽命令名、工作目录、归属会话、状态胶囊。
输出只给尾部 128px，带操作（停止 / 在终端打开 / 重跑）。要看全量就进侧栏——坞里不做滚动地狱。

运行中 → ✓ 完成 / ✕ 失败 / ■ 停止 · 🔐 等审批
04 / 双入口

坞是瞭望口，侧栏是深水区

同一个任务模型，两个入口，职责不重叠：坞负责发现与轻操作（看状态、停、重跑、跳过去）， 「文件」侧栏负责完整终端体验（全量输出、滚动、继续敲命令、清屏、复制全部）。文件侧栏本来就是会话的右侧抽屉， 加一个 tab 比新开一套终端窗口成本低得多，也不会多一层遮罩。

反过来，侧栏里新建的后台任务会立刻出现在坞里（并在坞里闪一下），前台终端任务只活在侧栏——按创建时的「运行方式」区分， 一眼能看出哪些离开侧栏也会继续跑。

05 / 终端页结构

左列表 + 右终端，沿用抽屉骨架

左侧 248px：任务按「运行中 / 等待审批 / 已结束」分组，行内是状态点 + 命令 + 用时； 「新建终端任务」常驻抽屉头右侧，任何时候都够得着。 右侧：42px 头（命令、cwd、状态、操作）+ 暗色控制台 + 底部续跑输入行。

「新建」不弹窗，直接在右栏换成表单——不叠第二层浮层，Esc 一次就能退回来。

06 / 新建表单

三个字段，一个默认值

命令（预填当前项目常用的那条）、工作目录（默认会话目录，可换）、运行方式（后台任务 默认 / 前台终端）。 下面一行小字说清区别，不让用户靠猜。⌘↵ 启动，Esc 取消。启动后焦点落到新任务的终端，可以直接看首屏输出。

09 / 边界

窄栏、多任务、无障碍

主栏 < 560px 时折叠条只留「点 + 数字」，隐藏命令名与用时；面板最多 8 行后内部滚动。 任务超过 20 条时列表分组折叠，运行中永远置顶。

折叠条是 role="button" + aria-expanded，Esc 可收；状态变化只在「失败 / 等审批」时用 aria-live="polite" 播报一次，跑起来的每行输出不播报。

工作台多列：只在聚焦列显示折叠条，展开面板不再浮在列里（列太窄），点开直接落到右侧终极端——避免每列都顶一条。
